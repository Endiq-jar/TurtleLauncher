# Icon provenance and animation contract

Every `res/drawable/ic_*.xml` in the launcher is a flat 24dp vector. The table below
records where each icon came from (the same `Source:` line is kept as an XML comment
in the file). The four exempt files (`ic_launcher_background`, `ic_launcher_monochrome`,
`ic_neoforge`, `ic_optifine`) are hand-authored artwork and are intentionally not
part of the imported set.

## Animation contract

* Every icon is displayed by `AnimatedIconView` or `AnimatedIconButton` (or by a
  `ShapeableImageView` that calls `AnimatedIcon.bindNamed` explicitly).
* `AnimatedIcon.styleFor` maps the resource name to one of ~40 distinct keyframe
  cycles; `seed` (derived from the same name) varies amplitude and direction so two
  icons with the same style still never move identically.
* Motion is **interaction-only**: a cycle runs while the view (or its clickable row)
  is hovered, pressed or focused, and a click earns exactly one play-through. Icons
  never animate ambiently and stop on pause/detach.
* WebP logos go through `AnimatedLogo` and additionally receive a slow kinetic layer
  (`AnimatedIcon.bindLogoMotion`) so they move on API 26/27 and while frames load.

## Colour

Imported icons tint from `@color/icon_tint`; the file-type family uses
`@color/file_icon_tint`. Both resolve to the pastel-green palette
(`@color/palette_secondary`) defined in `values/colors.xml` and
`values-night/colors_night.xml`.
